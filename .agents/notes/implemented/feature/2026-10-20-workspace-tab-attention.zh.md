# Agent Note：工作区页签的注意力标记

Status: implemented

[English](2026-10-20-workspace-tab-attention.md) | 中文

## 问题

横跨窗口的 Workspace 页签条只列出已注册的 Workspace，仅此而已。用户切换到其他 Workspace 后，Session 仍会继续运行，因此它的完成状态只出现在自己的侧边栏行上——而当该行属于另一个 Workspace 时，用户根本看不到这份列表。从页签条上无法看出哪个 Workspace 仍在运行、哪个已经结束，也无法判断结束的运行是否失败。某个 Workspace 的 Session 正等待用户处理——等待审批、计划待审或等待回答——时，页签看起来也和空闲时完全一样。仅把侧边栏的提醒搬到页签条上并不够：未查看完成的提醒不携带失败结果，而且它是 Session 级事实，会被“打开任意 Session”清除，而不是被“进入该 Workspace”清除。

## 决策

页签条在每个页签标题后渲染一个标记，由 `WorkspaceTabAttentionController` 派生，并通过页签注册的 `hooks` 隔间发布。

**待处理请求优先于一切。** Session 的统一状态带有待处理交互时，页签就显示该请求：审批或计划待审显示黄色警告三角，需要回答显示问号。这些标记在当前 Workspace 中同样显示，因为它们需要用户操作。多个 Session 同时等待时，按要求的强度取最高者——审批、计划待审、待回答——并且待处理请求优先于运行转圈和任何完成点。

**其次是运行活动。** 只要 Workspace 中任一 Session 的统一状态为运行中，页签就显示共享的 ongoing 转圈，即使该 Workspace 同时还有更早的未读完成。

**结束的运行留下一个点。** 最后一个运行中的 Session 结束后，未读完成会把页签标绿（运行成功）或标红（运行失败）。失败事实来自 `ui-session`：它在运行期间记住 Host 上报的实时 Agent 失败，并把它附加到运行状态事件记录的未读完成上，因此红点不需要新的 wire 事件。客户端列表基线不携带失败结果，因此客户端没有实时观察到的运行仍可能显示为绿色；失败只根据本连接观察到的事件分类。

**进入即确认。** 控制器维护自己的 Workspace 级确认集合。当前 Workspace 变化时，它确认离开的 Workspace 和进入的 Workspace 的完成，因此点击页签时圆点消失，而用户本就在该 Workspace 时结束的运行不会在之后冒出一个点。新的运行会清除该 Session 的确认，因此重新运行会留下新的标记。该确认集合刻意与 `ui-session` 的 Session 级 `completionUnread` 分开：进入 Workspace 不应清除已完成 Session 自己的侧边栏提醒，后者仍在告诉用户是哪一行完成了。

## 备选方案

- **把侧边栏的绿点复用到页签上。** 它已经会被打开主 Session 清除，因此当一个 Workspace 最近打开的 Session 并不是刚完成的那个时，点击页签后圆点仍会残留；它也没有失败分支。页签圆点需要自己的确认规则与结果。
- **通过 Host 列表上报轮次结果。** 列表摘要只携带运行状态，扩展 wire 或列表投影会为一个进程本地、且重新加载后本来就不会恢复的提醒增加持久字段。
- **从 Session 快照的 `lastAgentError` 推断失败。** 只有已物化（保留）的 Session 才有该快照；在另一个 Workspace 中结束的 Session 通常不会被保留，而这正是该标记存在的场景。
- **每次完成都发通知，而不是标记页签。** 通知队列会与对话通知、归档通知争抢，而且多个运行同时结束时，它无法回答“是哪个 Workspace”。

## 后果

- 标记是进程本地的：重新加载后没有完成圆点，与现有侧边栏提醒一致。
- 待处理标记不会因进入 Workspace 而被确认；它会在底层交互被回答或撤回后消失。
- 页签条现在注入 `uiSession` 服务来跟随其状态源；插件组合顺序不变，因为该服务是普通的 Cordis 依赖。
- 成员 Session 全部已归档的 Workspace 不显示标记；待处理请求优先于运行活动和更早的失败。
- 验证：`attention.client.spec.ts` 覆盖待处理优先级、运行优先级、绿/红结果、离开/进入确认、重跑更新、归档成员与销毁；`workspace-tabs.client.spec.tsx` 覆盖渲染出的图标、转圈与圆点；`ui-session.client.spec.ts` 覆盖失败附加及其清除。
